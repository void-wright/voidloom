# ============================================================================
# SUPPLY-CHAIN HARDENING — pinned == versions + SHA256.
# ============================================================================
# The three DIRECT dependencies below are pinned to EXACT versions and carry the
# upstream PyPI SHA256 hashes for every relevant artifact (sdist + the
# macOS x86_64 / macOS arm64 / manylinux / win wheels), so a tampered or
# substituted package on the wire is REJECTED at install time. einops and
# sqlite-vec are pure-data / prebuilt-binary wheels with no further runtime
# deps; sentence-transformers pulls a transitive tree (torch, transformers,
# huggingface-hub, …) that is platform-resolved.
#
#   pip's --require-hashes is ALL-OR-NOTHING: once ANY requirement is hashed,
#   EVERY install candidate (including transitive deps) must also be hashed.
#   Because the transitive set (esp. the torch wheel) differs per OS/arch, the
#   fully-hashed transitive lock MUST be generated on (or for) the target
#   platform. Two supported install modes:
#
#   MODE A — direct-pin only (this file, portable, THE DEFAULT):
#     The SHA256 hashes that used to live in this file have moved to
#     requirements.hashes.txt. They had to: pip turns on --require-hashes
#     the moment ANY requirement is hashed, which then demands == pins for
#     the entire transitive tree and made this documented default fail on
#     every machine. Measured on a cold install.
#       pip install -r requirements.txt
#     Installs the three pinned == versions; transitive deps resolve from PyPI
#     at their own latest-compatible versions. The top-level supply chain (the
#     packages a human chose) is version-locked; transitive integrity relies on
#     PyPI's TLS + the pinned roots. Good for the common case. (install.sh uses
#     MODE A by default.)
#
#   MODE B — fully hash-locked (strongest, per-platform, for --require-hashes):
#     On the TARGET machine/arch, regenerate a complete transitive lock:
#         uv pip compile requirements.txt --generate-hashes \
#             --python-version 3.10 -o requirements.lock.txt
#       (or:  pip-compile --generate-hashes --output-file requirements.lock.txt requirements.txt )
#     Then install with full verification:
#         pip install --require-hashes -r requirements.lock.txt
#     This locks the ENTIRE dependency tree (every transitive wheel hashed) for
#     that platform. Commit requirements.lock.txt per OS/arch you support
#     (e.g. requirements.lock.linux-x86_64.txt).
#
# Re-pin procedure when bumping a version: change the == below, refresh the
# hashes from https://pypi.org/pypi/<pkg>/<version>/json (the `digests.sha256`
# of each file), and regenerate the MODE B lock(s).
# ============================================================================
